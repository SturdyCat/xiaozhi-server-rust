# 插件化重构：ASR/LLM/TTS/VAD/AIUI 全部可插拔 + 目录重组

**目标**：引擎按"能力插件"组织（新增厂商 = 加一个文件 + 注册一行），应用层与插件层分离。**纯重构，行为零变化，客户端不动**。

## 目标目录结构

```
server/src/
├── main.rs                  # 入口：mod 树 + load_config + 装配
├── config.rs                # Config 聚合 + ServerConfig/AudioConfig + load()
│                            #   （各引擎子配置段迁入插件 mod.rs，此处 pub use 转发）
├── engine.rs                # Engines 装配器（保留：共享引擎池 + TTS 热切换）
└── app/                     # ★ 应用层（与引擎无关）
    ├── mod.rs
    ├── session.rs           # 会话状态机（AIUI 分支改走 FullChainEngine trait）
    ├── ws.rs                # 网关：路由/鉴权/握手/config/OTA 端点
    ├── protocol.rs          # xiaozhi 协议
    ├── transport.rs         # Transport trait
    ├── downlink.rs          # 下行音频
    ├── splitter.rs  ├── sse.rs
    ├── audio/{mod,opus,resample}.rs
    ├── firmware.rs          # 固件 OTA 托管
    └── voices.rs            # 发音人目录
└── plugins/                 # ★ 插件层（按能力分目录）
    ├── mod.rs               # pub mod 声明
    ├── asr/
    │   ├── mod.rs           # AsrEngine trait + build(cfg) + AsrConfig
    │   └── sensevoice.rs    # sherpa 实现（#[cfg(feature="sherpa")]）
    ├── tts/
    │   ├── mod.rs           # TtsEngine trait + TtsConfig/backend 分发 + 热切换支撑
    │   ├── kokoro.rs        # sherpa Kokoro 实现
    │   └── xfyun.rs         # 讯飞在线实现（原 xfyun_tts.rs：签名/错误提示/live 冒烟）
    ├── llm/
    │   ├── mod.rs           # ★ LlmProvider trait（新增，手动装箱 future 不加依赖）+ LlmConfig + build
    │   └── openai.rs        # OpenAI Responses 实现（SSE/工具调用）
    ├── vad/
    │   ├── mod.rs           # VadEngine trait + VadConfig + MockVad 占位
    │   └── silero.rs        # sherpa Silero 实现
    └── aiui/
        └── mod.rs           # ★ FullChainEngine trait + AiuiConfig + AiuiSession（原 aiui.rs 全迁）
```

## 关键设计

1. **插件 = 目录 + trait 实现 + 工厂 + 自带配置段**。新增厂商：在 plugins/<能力>/ 加文件、实现 trait、工厂加一行注册。TTS 工厂按 `backend` 字符串分发（现状），配置段 struct 随插件走（config.rs 保留聚合与 `pub use` 转发，TOML 格式零变化）。
2. **LLM trait 化**：`LlmProvider` trait，`chat_stream` 回调参数改 `Box<dyn FnMut(LlmEvent)->bool+Send>` + 返回 `Pin<Box<dyn Future>>`（手动装箱，与 Transport 同风格，不引 async-trait）。`Engines.llm` 改存 `Arc<dyn LlmProvider>`；session 两处调用点（流水线 + 测试台 llm_test）同步改。
3. **AIUI = 全链路插件**：定义 `FullChainEngine` trait（`turn(pcm) -> FullChainTurn{stt,reply,audio}`），AiuiSession 实现之；session 持 `Option<Arc<Mutex<dyn FullChainEngine>>>`，未来其他厂商全链路可插。讯飞系共享的 HMAC 签名 `signed_ws_url` 留在 `tts/xfyun.rs`（pub(crate)），aiui 引用并注释同厂商缘由。
4. **sherpa feature**：cfg 全部留在各插件实现文件内（sensevoice/kokoro/silero + audio），app 层无 cfg。

## 实施步骤（git mv 保留历史）

1. `git mv` 应用层 10 个文件 → `app/`，建 `app/mod.rs`；全库 `crate::session` 等路径机械替换为 `crate::app::…`；main.rs mod 树更新。
2. `git mv` + 拆分：tts.rs → tts/{mod,kokoro}.rs + xfyun.rs；asr.rs → asr/{mod,sensevoice}.rs；vad.rs → vad/{mod,silero}.rs；llm.rs → llm/{mod,openai}.rs；aiui.rs → plugins/aiui/mod.rs。cfg(sherpa) 随实现文件走。
3. LLM trait 化（签名如上，openai.rs 实现，session 调用点改 Box 闭包）。
4. AIUI trait 化（FullChainEngine）+ session 分支改走 trait。
5. 配置段迁移：五个子配置 struct 挪进插件 mod.rs，config.rs `pub use` 转发；TOML 键不变。
6. 全量路径修正；`cargo test`（无 feature）+ `DOCS_RS=1 cargo check --features sherpa`（cfg 代码移动，按规必须补验）。

## 不做（明确出界）

- 不做动态加载（dylib/ABI 插件）——编译期注册已是 Rust 生态的合理形态；
- 不改 session/ws 的编排逻辑与协议行为；不动客户端与固件仓库；
- 不在本轮给 macApp 补 [aiui] 配置卡（已知 footgun 单独跟进）。

## 验证

- `cargo test`（50 用例）全绿；`DOCS_RS=1 cargo check --features sherpa` 通过（无原生库下载）；
- 行为零变化：流水线/测试台/热切换/OTA/音色目录功能路径不改动，仅代码组织调整。
