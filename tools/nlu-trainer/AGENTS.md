# NLU 训练器

- `train.py` 从服务端配置模板生成语料、训练分类器并输出 `model.onnx`、`tokenizer.json`、`labels.txt`；不改变这三个产物及标签顺序的契约。
- 槽位值先去重，同名占位符共享一个组合维度；每模板输出最多 40 条去重且规范化空白后的句子，另设最多 4000 次组合展开预算（结束时可多探测一个未展开组合判断截断），不穷举笛卡尔积。所有有界展开候选在截取 `PER_INTENT` 前再全局去重；其中同句跨意图直接报错。**冲突检查不覆盖截断之外的组合**，不能声称全组合检查。`other` 是保留标签，不可声明为技能名。
- 不得用相同槽位展开制造所谓交叉负样本。`other` 使用闲聊和显式取消整条请求的句子；与任何正例碰撞时保留正例并计数。任务中的“不/不要”合法，例如“提醒我不要熬夜”，不能直接当成取消。
- 每次构建打印 `corpus_stats`（正负例数量、重复移除、负例碰撞跳过、各标签数量、展开扫描数、截断模板数和冲突检查范围）。空配置、空/缺模板、非正 `PER_INTENT` 和候选同句异标在加载 ML 依赖前报错。
- 使用标准库确定性分层切分：每类必须至少有 2 条去重后的实际选中样本（含 `other`），否则加载 ML 依赖前明确报错；每类 test 约 10%，至少 1 条且保留至少 1 条 train，输出 `split_stats`。不复制样本到 train/test，不靠评测泄漏兼容单句类。几十条无槽位模板可训练，无需配置槽位。
- 标准库回归：仓库根执行 `python3 -B -m unittest discover -s tools/nlu-trainer -p 'test_*.py' -v`；不需要 torch、联网或模型下载。
- 回归只验证语料生成与切分不变量；训练仍是模板合成语料的类内随机约 90/10 切分，小类因每侧至少一条而偏离此比例，即使去掉同句重复，也不代表独立真实语句的泛化能力。默认 `Trainer.evaluate()` 主要是 eval loss，不是业务准确率，也不能证明正例置信度达到服务端阈值。服务端构建路径将 `include_str!` 内嵌的受信训练脚本交给 Docker 内 `python -c` 执行，依赖镜像仅提供 ML 运行环境；脚本修复需发布包含新脚本的新服务。独立运行训练器镜像的 standalone 路径则需重建包含修复脚本的镜像。发布后仍须重新训练真实模型，并在独立正负例集上测分类、阈值通过率及拒识表现；本地脚本修复不等于线上已部署。
