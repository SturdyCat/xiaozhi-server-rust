# Dot 2 配置指南（中文整理版）

> 整理自上游 [wilbowes/EchoMuse docs/configuration.md](https://raw.githubusercontent.com/wilbowes/EchoMuse/main/docs/configuration.md)（快照 2026-10，main 分支）；以英文原文与固件源码为准，本文仅供本仓库开发参考。

每项设置实际做什么、什么时候会动它——用平实的话讲清。

## 0. 设置存放位置与作用域

- **Fleet config**（齿轮 → Fleet Config）：全体设备共用的默认值。
- **Per-device config**（设备页 → Config 标签）：每个分节头部自带 **Fleet / Device** 开关。

作用域**按分节**（per section），不是全有全无：留在 *Fleet* 的分节持续跟随全队值（含未来变更）；切到 *Device* 只有该分节归设备自有，其余照常跟随全队。小房间的 Dot 可以自有 **Ring** 场景与 **Microphones** 增益，同时照常吃进唤醒词、EQ、蓝牙的所有全队变更。（旧行为：一处覆盖即分叉*全部*设置，并永久冻结、脱离全队。）

显示 *Fleet* 的分节以只读形式呈现（不隐藏），继承的值始终可见；标签顶部横幅汇总 `Fleet` 或 `Local override (2 of 6)`（点名分节），**Revert all to fleet** 一键全部还原。把分节切回 *Fleet* 会**丢弃**它存的值——没有隐藏影子副本，几个月后再切回 *Device* 从全队值起步。

所有改动**立即生效**，无重启、无重建。Config 标签顶部恒为设备**网络（WiFi）**——永远 per-device、从不继承全队；其后按实际触碰频率排列：**Playback**、**Wake word**、**Microphones**、**Ring**、**Advanced**、**Bluetooth**、**Sendspin**。

**CPU** 表在百分比旁显示核心数（"27% · 2/4 cores"）：Dot 有 4 核且把不用的核停用，百分比是*醒着的*核的份额——同样的负载核越少读数越大；没有核心数陪着，会出现「什么都没变数字却近乎减半」的错觉。

另两个设备标签：**Status**——IP、固件、WiFi 网络、ESPHome 端口、当前音量、配置是全队还是被覆盖、资源表；其中 **Latency**（到设备的往返时延——>200ms 琥珀、>1s 红；这是 Echo WiFi 驱动实际提供的唯一链路健康信号，它不报重试与噪声数据）与 **Temp**（Dot 的 CPU 传感器；当 11 个传感器里最热者显著更热时取它——闲置约 33°C，所以琥珀即真异常；芯片热限流开始压 CPU 容量时也在此提示）；启用时还有蓝牙代理诊断面板；状态行 `Online`，或 `Offline`（含最后听见设备的时间）。**Activity**——语音回合历史：听到什么、如何转写、唤醒分、播放欠载、near-misses；**Save utterances** 开启时附每轮录音（可回放/下载）；**Save wake-word samples** 开启时另列分数候选与检测命中供复审标注。历史存控制器数据库、跨控制器与设备重启存活；小时级硬件趋势（CPU/内存/WiFi 信号）保留 180 天，API `/api/devices/{id}/activity?days=N`。

## 01 — Playback（响应听感）

调参前先知道两件事。**改动约四秒后才听得到**：音频提前数秒下发，此刻在放的是你动控件之前处理的；判结果先等五秒，勿快速来回切——听到的永远是旧音频，会误以为没生效。**要在你正在听的设备上改**：该设备 Playback 分节已 Device 化时，改全队默认不影响它，而保存照样成功，症状是控件「怎么调都没反应」。

| 设置 | 取值 | 默认 | 语义 |
|---|---|---|---|
| Equalizer（8 faders + presets） | Flat / Warm / Clear / 自定义曲线 | Flat（推荐） | 塑造扬声器一切的音色。新音效固件下 Echo 已自我校正，Flat 即其自身声底；Warm 增形体、削高频；Clear 削低频、增存在感；拖任意 fader 得自定义曲线。升级把旧 **Speech**/**Music** 预设重置为 Flat（新音效下会双重加 Bass）；自定义曲线保留 |
| Response level | Low / Medium / High | Low | 语音响应相对常规音量的增益：Medium 加 6dB、High 加 12dB。音量键仍同时动媒体与语音，此设置只在量程内让语音更响；接近最大音量时增益渐衰为零，不会顶破满幅；唤醒音独立、走 Wake sound level。旧固件无法应用，控件禁用并提示需新固件 |
| Speak while the reply is written | on/off | off | 开=HA 拿到**第一句**就开始说（长回复更早出声；收益≈首句到末句的时间差减约 1 秒首句合成，短回复收益小）。仅当会话代理与 TTS 都可流式时 HA 才提供，否则无效、整句播完再放。**代价是速度**：模型写慢于语速（约 <4 tokens/s）或 TTS 慢于实时，设备句间无料可播——静默等待、内容不丢但会顿。开上试几条长回复，断断续续就关。开启后回复起播等待（默认 30 秒；插件 **Reply wait** 可调，#805）只需首句满足 |
| Speaker protection | on/off | on | 一个开关两段：低频护卫——约 115Hz 以下听不见却推动音盆、糊掉中频（俗称薄、闷、铁罐声）；移除后中频更清、大声内容还略*响*（限幅器不必再为听不见的 Bass 峰压住整体）；小声段低频保留——是护卫不是滤波。加 EQ 限幅器——防 EQ 提升削波（实测普通响应加小 Bass 提升时近 5% 采样削波，听感为刺耳/爆音）。**曾是五个控件、刻意合一**：五者皆无法用耳朵判断且互偿（平 EQ 开护卫整体变 7.7dB、全 +12dB 时仅 0.2dB——限幅器把护卫拿走的还回去；depth 滑条全程仅 0.14dB）。原 ceiling/release/depth 仍生效、仍可经 API 触达，只是不在面板。分频点与曲线形状取自 Amazon 自家固件在同一扬声器上的实测，非猜测；我们的默认 depth 比 Amazon 温和（其位于一条未测得的 EQ 曲线之前，见 issue #247） |
| Duck depth | dB | −18dB | 语音压音乐多深。音乐在语音回合中**继续播放**（不暂停），答句混在安静的垫底上，答毕垫底回升。−6/−10 音乐更在场；−25/−30 答句期间近乎静默。按耳朵在放音的房间里定，无普适值。响应本身从不被压低，只压其下的音乐——答句被音乐盖住时动这里，不是动音量。需固件 **v2.10.0+**（设备端混音——控制器领先约四秒，说唤醒词时那四秒音乐已在 Echo 上，控制器无从再改）；旧固件滑条禁用，退化为整轮暂停/恢复 |
| Volume | — | 跟随实际使用 | 音量**跟随你实际用到的值**且跨重启：每次变更（按键、HA 滑条， anywhere）都被控制器记住、重连时恢复。本节**无音量滑条**：旧滑条只在开机后首个配置推送时生效、有误导（真实音量变化还会覆盖它），现于 **Status** 标签只读显示，改音量走 HA 或设备按键。无论分节开关如何**从不继承全队**（否则设备会以别个房间的音量回来）。**2.20.0 起量程顶变了**：旧版把 codec 数字音量推过只能削波的区间（实测中点以上三键 65% 失真、顶格 89% 且不再更响；原生 Alexa 从不碰那一段，故 EchoMuse 开大声反而更难听）。现止于 codec unity gain——最大档比以前轻、其下更干净；HA 显示的百分比也上移（同物理响度读数更高，因刻度不再含纯失真段），带音量阈值的自动化请复核。物理按键全程约每按 4dB，青色弧跨同一量程、每按必动 |
| Volume button sound | on/off | on | 空闲时用 Dot 物理音量键改音量，在**新选定的音量**上播一声短促低哔（快衰减）。HA 改音量、语音/音乐播放中不响；最大音量再按音量+重放哔声让上限可闻。跟随 Playback 分节的 Fleet / Device 作用域 |
| Mute | — | — | 静音由**设备自身**记忆：静音的 Dot 跨重启、断电、固件升级保持静音（红环也在），无论控制器是否可达 |

## 02 — Wake word

设备如何判定你说了魔法词。默认 Dot 自己做这项工作、听到词之前不上传任何东西；也可改为控制器检测（Dot 持续推流），见 **Wake word detection**。

| 设置 | 取值 | 默认 | 语义 |
|---|---|---|---|
| Wake word model | Hey Jarvis / Alexa / Hey Mycroft / Hey Rhasspy / 自定义 | — | 四款预训练识别器，选一个不与常用词撞车的（家里还在跟真 Alexa 说话就别选 Alexa）。自定义：用 `oww_forge/` 训练后经 **+ Custom model** 瓦片上传 `.onnx`——存控制器数据卷、成瓦片列在官方词旁、选中即生效；未选中瓦片的 `×` 删除之；上传先校验，跑不起来的文件带理由拒收——校验只证明模型能跑，能否听见它的词要靠你喊它实测。**设备本机检测时须先把识别器装进设备**。四款官方词开通时预装、切换即时免拷贝；自定义词在选中时拷贝——到货前设备继续应答**当前**词（通常数秒），拷贝失败留在原词并记日志，绝不会处于「听一个没有的词」状态。此机制前开通的设备下次连接自动补齐缺失官方词。**改唤醒词会让设备在 HA 短暂重连**：HA 仅在连接时读卫星的唤醒词配置，控制器断开重造该连接以让新名字出现；期间该设备**全部实体** unavailable 后立刻恢复（语音助手、媒体播放器、action button、环境光传感器、Microphone Muted 传感器）。用 state 触发器的自动化会被触发——事件实体恢复时带回上一事件、看似又被按了一次，需按下方 YAML 排除 |
| Arbitration window | ms | 700 | 多台 Echo 仲裁：过去两台都听见会开两个竞争对话；现在**只应答一台**——听得最响的那台（通常是你所在房间），窗口内听见同一词的其他 Echo 静默让位。≥2 台在线时唤醒最多等 0.25 秒汇总各台；单台无等待；窗口只决定此后多久第二台还算「同一句话」；`0` 关闭仲裁。controller 2.26.0 前是先听见者应答（缘由见 listening.md） |
| Wake sound | on/off | off | 听到唤醒词播短促上升音。默认关（唤醒与请求之间多一拍）；首先是**无障碍**选项——没有它灯环是「在听」的唯一迹象，隔房间或看不见时无用处。**Wake sound level** = Quiet / Medium / Loud，电平与 Echo 音量无关，调低音量的 Echo 仍能确认听到你。只有应答的那台播：让位的、身后没有 HA 的都不播——即 Echo 须先等控制器回话（一个网络往返）。需固件通告 `wake_cue`；旧固件开关禁用并说明 |
| Sensitivity（Precise ↔ Eager） | 连续调节 | — | 识别器须跨过的置信门槛。向 **Precise**：假唤醒少（不被电视触发），偶而忽略你；向 **Eager**：抓得更稳，偶有幻唤醒。**调法**：Status 标签数 **near-misses**（分数接近却未触发的时刻）——被忽略且 near-misses 上升→向 Eager 一步；没人说话却唤醒→向 Precise |
| Barge-in | on/off | — | 允许唤醒词**打断正在进行的回合**——朗读中（或还在想上一个问题）说唤醒词即停下听你。**先开 Echo cancel (AEC)**：打断靠播放时麦克风保持开启，AEC 防它听见自己。On this Echo 模式下打断由 Echo 本机侦听，回放期间除非听到唤醒词否则不上传任何东西。**barge threshold** 是播放期间的唤醒置信门槛，反直觉地**低于**平时门槛：扬声器在麦克风处远比人声响，你的声音压过回放时得分更低——实测约 0.3–0.5，而普通唤醒 0.5。**默认 0.25（自 0.05 上调）**：旧值按短回复定、长回复下失效（要故事时助手自述得分至 0.18、句中自我打断——连续语音总有片刻像唤醒词）；现另要求**连续两次检测**，单个野帧无害。回应自我切断→调高；打断失灵→调低——但先查 AEC，那才是更常见的原因。**静默 thinking 停顿期间适用普通唤醒灵敏度**（2.21.0 起）：此前 thinking 有单独更低门槛、落在房间噪声可达区间，背景声可取消你刚问的问题并在转写前重开麦克风。实测 505 次 near-miss、30 次真检测：真唤醒无一低于 0.502，噪声最高 0.462；旧低门槛在补一个别处已修的缺陷。注意 **Barge threshold** 从不管 thinking 阶段——调它既非修法、现在调低也无碍。**打断之后**：设备停话立听——一口气说唤醒词+新指令两句都听到，无须等第二次提示（2.20.1 起正常；此前打断切掉回答但后续命令收不到，得再说一遍）。**打断不可撤销**：说完唤醒词再沉默，原回答作废而非恢复——HA 无法重启已放弃的回复，回合安静结束 |
| Speex denoise | on/off | off | 对音频跑降噪**仅用于唤醒词评分**（你的实际命令不动）。常驻背景噪声（电视、空调）且唤醒不灵的房间值得一试——「开了对比看」型选项 |
| Wake word detection | On this Echo / On the controller | On this Echo（新装） | 唤醒词在哪被听见，逐台设置。**On this Echo**：Echo 自己听唤醒词、**听到之前不上传任何东西**；此后上传你说的话直到停口，再回本机监听；回放插话（barge-in）也在 Echo 本机听。**On the controller**：Echo 把麦克风**持续**推流到控制器（在你的局域网上）、控制器来听——私有监听之前的旧工作方式，此前的安装保持该设置直到你改。**On this Echo 须知**：需设备上有固件外文件——ONNX Runtime + 唤醒模型约 15MB，`/data/local/share/echomuse/oww`，Echo 连接时控制器安装；装好前 Echo **button only**（不会悄悄回退推流，面板说明原因）；常耗约 **0.4 核**（Dot 2 扛得住，Status → Resources 可见）；需较新固件（旧固件任何模式都推流，面板显示 streaming 并提示「更新固件以获得私密监听」）；误唤醒仍会把几秒你不想发的音频发出去——所有唤醒词系统皆然，Amazon 亦然；这些回合 Activity 无控制器分、near-miss 显示 `—`（控制器从未听到音频，无从比较）。**混合队型没问题**：一句唤醒多台时由*先听到*你的一台应答，无论哪侧检测——claim 按音频采集时刻比较而非消息到达时刻，慢链路不会答错房间 |
| Wake-word sample capture | Save wake-word samples / Minimum sample score / Both (compare) | off | 为改进自定义唤醒模型采集样本。开启后控制器维护短内存音频缓冲：分数达 **Minimum sample score** 或真实唤醒触发即存片；**Both (compare)** 模式还存 Echo 上报的越阈。片含峰值前后音频，不持续把房间音频写盘。在设备 Activity 面板复审，逐片标注 **Wake word** / **Not wake word** / **Unsure**——构成可复审的正负样本集，**不会**自动训练或改模型。标注另把片复制进按标签组织的永久无上限归档（旁附分数与模型的小元数据文件）——值得留的片因此躲过下方每台 50 片上限、不会被裁。两处均为明文 WAV：复审片 `data/recordings/wake_samples/`（每台至多 **50 片**，最旧自动裁）、归档 `data/recordings/wake_samples_archive/<label>/`（无上限、无人删）——均不上传。关闭采集立即停新片，已存（复审或归档）原地不动。默认 off；片 **admin-only**（可能含普通语音）；两个检测器都低于所选最小分的短语不会被采。设置下一行显示 Echo **实际**在做什么（依其自报而非设置）：listening privately / streaming / **button only**（含原因）。主页有全队一行汇总（如 *1 of 3 connected Echoes streams audio continuously*）。音频何时离开 Echo 的完整规则见 listening.md |

改唤醒词时排除 HA 状态触发器误触发的写法（action button 事件实体最典型）：

```yaml
trigger:
  - platform: state
    entity_id: event.your_device_action_button
    not_from:
      - unavailable
      - unknown
```

这不是设备故障，且只在改唤醒词时发生。

## 03 — Microphones

你的声音如何被采集。这些设置经过精心调校——多数人只应动预设。

| 设置 | 取值 | 默认 | 语义 |
|---|---|---|---|
| Pickup presets | Omni / Front / Rear | Omni | Dot 有 7 个麦克风，命令期间可偏向离你声音最近的麦。**Omni** 一律用中央麦——安全选择，也是方向拾音异常时的回退；**Front / Rear** 恒偏一侧——贴墙或挨电视的 Dot，把拾音*背向*噪声；方向拾音开启且未固定方向时，设备每次唤醒自动选麦（见 pipeline 文档 "lock-back" 一节） |
| MICPGA / Digital gain | 数值 | Amazon 出厂值 | Dot 音频芯片内部的硬件放大电平，与 Amazon 出厂值一致。**别动**：错值会同时失真全部麦克风 |
| Mic gain (dB) | dB | 24dB | 施加在原始 24-bit 麦克风信号上的第一级软件增益——原始采集极安静，无此增益语音识别经常失败。仅在很大房间的设备仍测得偏小时上调（过头设备日志报 "clipped" 采样）；见削波就向 0 降 |
| Beam angle / Beamforming | 角度 | −1（自动） | 拾音预设背后的原始控件。Beam angle `-1` = 每次唤醒自动选向；其余值固定拾音方向角（0 = 音量+键一侧，顺时针）。预设替你设好这两项 |
| Noise suppression | on/off | off | 清洗**送语音转写**的音频（仅此——唤醒词监听不动）。用跑在控制器上的小型神经降噪器（DTLN），Dot 零负载。对*稳态*噪声最有效——风扇、空调、家电哼声、转写经常含混的房间；去不掉别人说话与电视——那要用波束方向避开。默认 off，逐设备开启对比转写。抑制上限 20dB：被判为噪声的段落被大幅压低而非整段抹除（上限出现前可能把轻声语音完全静音——一两个词凭空消失而非含混） |
| Echo cancel (AEC) | on/off | off | 教麦克风*减掉 Dot 自己的声音*。收益：应答期间与刚结束能听清你（追问好得多）、自声不扰监听逻辑、barge-in 的前提。默认 off，逐设备开启并查设备日志 `[aec] att=` 行在应答期间爬升。两个旋钮：**AEC delay**——播放与麦克风所闻的对齐，**保持 0**（实测本硬件的正确值，麦克风管线自身缓冲已吸收扬声器时延；抬高可能静默令取消完全失效）；**AEC tail**——建模的房间回响量，默认 300ms，空旷大房间向 500 调 |
| Save utterances | on/off | off | 保留近期语音回合的音频，让你*听*实际送去转写的内容——Activity 每轮出现 ▶（就地播放）与 ⤓（下载 WAV）。存的是**转写实际收到的音频**：降噪开着就是清洗后版本而非原始麦克风——刻意的，转写错误时唯一能解释它的录音就是识别器真正听到的那份。这是回答「我的麦克风到底行不行」的正道：否则只能从含混转写瞎猜（房间吵？增益低？降噪吃词？）；三十秒试听通常定案，也是 A/B **Mic gain**、拾音预设、**Noise suppression** 的唯一可行办法（同一句话前后对比）。**默认 off、开启前想清楚**：这是唯一在控制器存可辨识语音的设置。存什么：**每设备最近 10 轮**，控制器数据目录明文 WAV，新录覆盖旧录；只存送识别的音频——常开的唤醒词监听被持续丢弃、从不写任何地方。关闭立即停录，但**已存文件原地保留**（刻意：别毁掉你对比到一半的样本），直到被新录音挤出（需重开）或删除设备（连带删其录音）；急清可删控制器 `data/recordings/` 下的文件。很久以前的回合无按钮 = 录音已滑出最近 10 条、回合历史活得比它久。回放/下载与转写文本均 **admin-only**（服务器端强制，不只是页面隐藏——HA 插件全家都能开面板，只读账号只得回合时序、分数与结果，无语音） |
| Wake word microphone | Centre / MK1–MK6 | Centre | 七麦中谁来听唤醒词。**Centre** 适合几乎所有 Echo；MK1–MK6 是边缘六麦，供中央麦克风损坏、不再唤醒的 Echo 备用。旧固件忽略此设置并显示控件禁用 |

## 04 — Ring

对话期间灯环的用色。场景即时生效、可逐设备不同。现行固件（v2.9+）设备**自行渲染动画**——控制器每次状态变化只发一条「播这个动画」指令，转圈不受 WiFi/控制器负载影响而保持丝滑；响应播报时灯环**随音频节律起伏**（亮度跟随扬声器实际输出电平）。控制器中途消失时灯环自行超时而非永远转。旧固件回退控制器逐帧渲染。

| 设置 | 取值 | 默认 | 语义 |
|---|---|---|---|
| Ring scene | Standard / Airy / Malevolent / Pride / Custom | — | **Standard** 经典绿；**Airy** 淡静天蓝；**Malevolent** 深绯聆听环 + 余烬色转轮；**Pride** 旋转彩虹；**Custom** 自选 **Listening**（录音时实心环）与 **Thinking**（处理时转轮）两色 |
| （每场景恒定元素） | — | — | 两样永不随场景变：**红色静音环**（红永远=麦克风关闭，隐私指示而非装饰）与青色音量弧。「哪只麦在听」的方向高亮也自动适配：提亮场景环色而非画死绿色。音量弧持环约两秒、防回合动画瞬间抹掉——但**按 action button 立即取消**：调完音量接着说话，立刻看到聆听环 |
| Remote volume arc | on/off | off | 选择加入的无障碍设置：开启后来自 HA、自动化、EchoMuse 面板或其他远端播放器的音量变化也显示同款青弧约两秒。默认关——否则远端变更会让灯环无故亮起。物理音量键恒显示弧；音量设 0（含 HA 静音）、重复当前音量、开机恢复保存音量永不显示。旧固件显示禁用直至升级。弧与 HA 滑条对「一半」的理解不一致：HA 的 50% 只亮约四分之一环——[#783](https://github.com/wilbowes/EchoMuse/issues/783) |
| 回合如何结束 | — | — | 灯环用**节奏**而非颜色告诉你对话为何结束（红/橙/青已占静音/无控制器/音量）：**一次慢搏动**=在听但没听到话；**几下快闪**=出了错（HA 报错或没收到语音）；**环直接熄灭**=正常结束或你自行取消。环现在在音频*真正*播完时熄灭，而非控制器估算的时刻——慢 WiFi 下旧估算可比 Dot 说完提前数秒熄环 |
| Meter response（Advanced） | Decay / Attack / Gamma / Floor / Reference / Curve | 按语音调校 | 响应播放时环随实时扬声器电平起伏；Advanced 面板控制起伏强度——设备本地渲染，改动下次响应即生效、无重启：**Decay** 下降快慢（高跟随单个音节，低读作慢涌）；**Attack** 峰起速度；**Gamma** 对比度（高则摆动更显眼）；**Floor** 静默期亮度（`0` = 词间全黑）；**Reference** 映射到全亮的扬声器电平（低更灵敏）；**Curve** 低于 `1` 把轻声辅音抬进可视范围。纯口味设定——正因如此放在面板而非烧进固件。默认按语音调校；环看着太静先升 **Decay** 与 **Gamma** |

## 05 — Advanced（只影响按键对话）

本节一切**只作用于按键对话**（按 action button 无唤醒词说话——*长按 hold* 是另一手势，改为向 HA 发事件）。唤醒词对话无视本节全部内容——由 HA 自身的语音检测管理。麦克风静音时 tap 无动作，hold 仍发事件：静音只哑语音、不哑按钮。

| 设置 | 键名 | 取值 | 默认 | 语义 |
|---|---|---|---|---|
| Tap fires an event | `buttonSingleTapEvent` | on/off | off | 把 tap 变成 HA 事件而非对话开始，可绑任意自动化。开启后设备完全不再由按钮发起语音回合；唤醒词不受影响，hold 仍发 `long`。静音时 tap 也发——它是事件不是语音。需固件 v2.10.0+，旧固件禁用并说明。**破坏性自动化绑 hold 别绑 tap**：按钮无鉴权，台面上的音箱被误 tap 的概率远大于被误长按四分之三秒 |
| Multi-tap window | `buttonMultiTapMs` | ms | 0（不分组） | 设为 >0 后 tap 分组为 `single` / `double` / `triple`；代价是*每个* tap 都延迟一个窗口——没有第二下跟上才能定为 single。**用 350ms**：低于约 300ms 会同时与人手时序（双击约 150–400ms 间隔）和网络抖动冲突——间隔目前按 tap 到达控制器的时刻测，而非设备上测；繁忙或远距设备可能需要更大。0 = 不分组，tap 立即发 `single` |
| Auto gain (AGC) | — | on | on | 按键回合自动均衡你的音量——耳语与喊叫效果相近。此处无害；**刻意永不**用于唤醒词监听（增益随房间噪声漂移曾是「几天后不响应」bug 的根因，已被永久逐出该路径） |
| Speech gate — Threshold | — | 前置增益单位 | 0.001 | 判「是不是语音」的响度门限。以前置增益单位计（mic gain 不改变该数字含义）。默认值经实测校准；仅真实嘈杂房间略升（0.003–0.005）。现行固件用小型语音模型（Silero，控制器随唤醒词文件一并安装）判定「是否语音」，大声非语音——压低的垫乐、风扇、电视——不再把回合拖住不关；此阈值仅为模型装好前的回退；两道门限时间无论如何都生效 |
| Speech gate (ms) | — | ms | — | 多长连续语音才开门。高 = 忽略短暂噪声，但削快语速者 |
| Silence gate (ms) | — | ms | 900 | 多长静音结束你的回合。高 = 句中停顿不被切断，低 = 响应更跟手；被截断就升到 ~1200。（v2.9.4 注：这两个时序如今严格按配置执行。旧固件按约 5× 时长执行——对麦克风真实批大小的计数 bug——按键回合会多挂几秒静音才结束；升级后觉得变跟手是这原因，慢语速者被削就调大 silence gate） |

## 06 — Bluetooth

| 设置 | 取值 | 默认 | 语义 |
|---|---|---|---|
| Bluetooth proxy | on/off | off | 把 Dot 变成 HA 蓝牙代理：被动监听 BLE 广播（在场信标、BLE 温湿度传感器、手机手表——Bermuda 之类房间在场系统）转发给 HA。在 HA 中代理作为**独立 ESPHome 设备**出现（名 `<label> BT Proxy`），与语音卫星互不相干——增删忽略都不碰语音侧；接入后其扫描器与 ESP32 蓝牙代理一样喂 HA Bluetooth 集成，另有诊断传感器计数收到的广播。**启用前知道三件事**：(1) 开启会**永久**把 Dot 蓝牙芯片切离 Android 协议栈（跨重启存活）——EchoMuse 用不到 Android 蓝牙，但该设备从此无法原生蓝牙音箱配对；(2) 代理本身**只收不发**（被动扫描）——需要连接才能读数/受控的设备要再开下面的 **Allow connections**；(3) Dot 的 WiFi 与蓝牙**共用一根天线**，扫描占 WiFi——Dot 听你说话、收回复、跑控制台或升级时扫描**自动暂停**后恢复，每轮语音损失几秒在场追踪 |
| Allow connections | on/off | off | 允许 HA 经 Dot 连接蓝牙设备：智能锁、SwitchBot、一切不满足于广播的设备。默认 off；需 **Bluetooth proxy** 已开且固件支持（不支持时开关禁用并说明）。开启后有一件必须跟进的事：**代理与 HA 的连接改为加密、HA 会索要加密密钥**——保存设置，按开关下 **Show encryption key**（仅 admin），在 `<label> BT Proxy` 设备要求重新配置时粘进 HA；粘之前该代理连广播也停发（HA 连不上它）。此后该 Dot 密钥恒定。密钥强制、无跳过项：连接能操控对端 whatever，无密钥则你网络上的任何东西都能借代理这么干——当密码对待。再关掉 connections 则代理回到无加密并断开所有连接。**限制**：每 Dot 同时 **3 连接**；**无配对**——要蓝牙配对（bonding）的设备会拒，多数锁与 SwitchBot 在应用层自加密、不需要；**占用连接即占在场追踪**——扫描与连接共享 radio，连接期间广播捕获约减半；连接空闲五秒后转慢节奏省开销，静默后首条命令约一秒；Dot 失去控制器时连接断开、HA 重连之。诊断在设备 **Status** 标签（Bluetooth proxy 面板）：扫描器状态、所见广播数、附近设备数、HA 是否连接并在接收 |

## WiFi（设备页 → Config 标签顶部）

免 ADB 把设备迁到别的 WiFi：顶部小节显示当前网络、信号与 IP，可扫描可见网络，带确认步骤切换。切换按**防变砖**设计：设备自行应用变更，须过三关——加入网络、拿到 IP、**重连回本控制器**——任一失败（口令错、DHCP 故障、能上网却连不到控制器的隔离访客 VLAN 等）自动恢复原网络并告知原因；切换中途断电也能恢复：未确认的变更开机回滚。留约两分钟掉线窗口。

### Static controller endpoint（Config → Advanced → Controller address）

设备平时用链路本地 mDNS 找控制器；若设备经路由隧道或 mDNS 过不去的隔离 VLAN 才能到控制器，在此列地址。**全队生效，无逐设备覆盖**：

- 每条 = IP 或主机名 + 设备端口 + 加密（TLS）端口。初始为本控制器自身；TLS 端口 `0` = 该地址无加密监听。
- Echo 按序尝试各地址、每个两次，再 mDNS 找一次，如此循环。错地址只会拖慢重连，不会让 Echo 找不到控制器。
- 保存即写所有在线 Echo，其余下次连接获得；下次重连即用、无需重启。开通向导按运行时的列表写入新 Echo。需固件 v2.16.0+，旧固件忽略并继续用 mDNS。

列表落地为设备上的 `/data/local/etc/echomuse/controller.json`，固件每次重连尝试时重读。仍可手写该文件，例如给必须永不触达其他控制器的测试队关掉 mDNS 回退：

```json
{
  "endpoints": [
    {"host": "10.20.40.110", "port": 8767, "tls_port": 8770},
    {"host": "controller.example.internal", "port": 8767, "tls_port": 8770}
  ],
  "mdns": false
}
```

面板列表优先：为空时控制器不动手写文件；一旦设置列表，每次都覆盖所有 Echo 上的文件（含手改）。开通向导更进一步：按设置写入；未设置时**删除**设备上已有的 `controller.json`——前一套设备的另一控制器地址不得残留。

## Controller settings（`.env` 文件）

服务器上一次设好，改动需重启控制器：

| 设置 | 语义 |
|---|---|
| `SERVER_IP` | 控制器主机的局域网 IP——告知设备连接的目标。留空则从本机探测；探测不可靠时控制器宁可拒绝启动也不广播猜来的地址，探测值疑似容器网桥会告警。mDNS 仅在该地址所在接口通告——HA 必须同网才能发现 Echo；地址不属于本机时控制器记日志并改为所有接口通告 |
| `DB_PATH` | 数据库存放处；设备证书与录音存在其旁。发布镜像默认 `/app/data/echomuse.db`（compose 文件挂载的目录），有无 `.env` 都跨升级存活；裸机安装应显式设置 |
| `OWW_MODEL` / `OWW_THRESHOLD` | 唤醒词/灵敏度的启动默认——面板上的值覆盖之 |
| `DEVICE_APPROVAL` | `strict`（每台新设备人工批准——推荐）或 `auto` |
| `SERVER_TLS_PORT` | 加密设备链路（wss）端口——默认 8770，`0` 关闭。Echo 配对后**勿设 0**：持有凭据的 Echo 不会回退明文链路。设备一持凭据即自动切换：来自向导、批准新设备或配对（长按 Echo 的 action button 7 秒——v2.19.0 前固件为 5 秒——再 **Approve pairing**） |
| `REQUIRE_DEVICE_TLS` | **仅在所有设备 Status 标签显示 "wss (TLS)" 之后**设 `1`——此后控制器拒绝未加密或无 token 的设备连接 |
| `EM_EXTRA_CA_CERT` | 要信任的 PEM CA 证书路径——HA 或你拉流的媒体服务器用自建 CA 的 HTTPS 服务时需要，见下 |
| `EM_TTS_WAIT_TIMEOUT` | 等 HA 回复开始的秒数，超时放弃回合——默认 30，上限 120；会话代理用工具需要更久就调大。插件同款选项名 **Reply wait (seconds)** |

完整清单见 `.env.example`。

### 加密设备链路

控制器首启自建 CA（存数据库旁 `tls/`），明密双监听。每台设备两份凭据——CA 证书 + 私有 token——由开通向导自动安装，或对既有设备用 Status 标签的 **Secure link** 按钮推送。持凭据设备下次重连起走加密连接；Status 标签 **Link** 行显示各设备当前模式。全队都显示 `wss (TLS)` 后设 `REQUIRE_DEVICE_TLS=1`，彻底锁死明文连接。

### HA 藏在自建 CA 之后

HA 用自建 CA 证书的 HTTPS 服务时，EchoMuse 拉不到语音回复、**每轮静默收场**——控制器正常启动、Echo 照常唤醒、无音频到达，界面无一字解释，日志里是证书校验错误。

**先试免证书方案**：HA 本体仍听明文 HTTP、TLS 由前置（反代、Nginx Proxy Manager、Cloudflare）处理时，把 HA 的 **internal URL** 设为 `http://<其地址>:8123`。HA 依该设置拼音频 URL，抓取变为本地明文，问题消失——EchoMuse 在你自己的网络上、这一跳是本地的，什么也不损失。

**HA 本体配了 `ssl_certificate` 时**，把 CA 交给 EchoMuse：

- **Add-on（插件）**：CA 证书（PEM 格式）放进 HA 的 `ssl` 目录，把 **Private CA certificate** 选项设为 `/ssl/<文件名>`。插件只读该目录。
- **Container（容器）**：挂载证书，把 `EM_EXTRA_CA_CERT` 指向*容器内*路径：

```yaml
volumes:
  - /path/to/internal-ca.crt:/certs/internal-ca.crt:ro
environment:
  - EM_EXTRA_CA_CERT=/certs/internal-ca.crt
```

必须是 **PEM** 文件（`-----BEGIN CERTIFICATE-----` 那种）；DER 先转换：

```bash
openssl x509 -inform der -in ca.der -out ca.crt
```

文件缺失、不可读或非 PEM 时，控制器**拒绝启动并指明是哪种**——而不是启动后每轮失败、错误还联系不上这个设置。

**媒体播放同样校验**：媒体播放器经 ffmpeg 拉流——Music Assistant、电台、交给 `play_media` 的一切；旧 ffmpeg 构建对 HTTPS URL 接受*任意*证书（无人会选的构建默认），现媒体 URL 与普通抓取同样校验。自建 CA 的 HTTPS 流需要与上文相同的设置；流被拒时日志会说明并指向这里。

## 什么会离开你的网络

EchoMuse **无遥测**：无使用上报、无分析、无崩溃报告、无安装计数——不报你用了哪些功能、几台设备、甚至不报你装了它。这是刻意决策而非疏漏：项目的存在意义就是把云语音助手请出你的网络，悄悄加个 ping home 就毁了运行它的理由。一个明说的后果：**包括维护者在内，没人知道有多少人在用 EchoMuse**——普及度只能从 GitHub star 与发布下载数猜，这就是交换条件。

### 唯一的出网连接

控制器每小时访问 `api.github.com` 问最新版本，供面板提示可更新并展示说明；你选择更新设备时，固件二进制此刻从 `github.com` 下载。就这些。请求不带任何标识符——普通未认证 API 调用——但照例向 GitHub 暴露你的公网 IP，与 `git clone` 或浏览器开仓库同级。

系统配置里 `update_check_interval`（秒，默认 `3600`）可调：`86400` = 每天一次；`0` = 彻底关闭——控制器此后**零出网连接**，面板显示最后已知的版本信息而非空白。重新开启无需重启即生效；关闭不禁用 Updates 标签的 **Check now** 按钮——那是主动请求，按下照常问 GitHub。（controller 2.21.0 前 `0` 是反的——不是停而是去掉间隔连续轮询，直至被 GitHub 限流；在旧版本设了 `0` 并一直放着的，升级即修复，无须回改。）

### 永不离开的

- **语音音频与转写。** 麦克风音频走设备→控制器→HA，全程局域网——设为 **On this Echo** 的，仅在听到唤醒词之后、到你停口为止；设为 **On the controller** 的，持续到控制器。之后去向由你的 Assist pipeline 决定——HA 配了云端语音转写就送云端；EchoMuse 自身只送 HA，别处不去。
- **话语录音**（`saveUtterances`，默认 off）——存数据库旁磁盘、从不上传。回放/下载是 **admin-only**，看回合的转写文本也是（HA 插件上全家用户都能开面板，只读账号只得回合时序、分数与结果，无语音；服务器端强制）。
- **唤醒词样本片**（`wakeClipCapture`，默认 off）——同话语录音一样落盘、从不上传。回放、下载、标注、删除均 admin-only；标注另把片复制进按标签组织的永久归档——同样从不上传、admin-only。
- **设备序列号、WiFi 凭据、网络名与你全队的配置**——只存控制器数据库。
- **Support bundles**——仅在你请求时生成，是否分享由你定；刻意不含语音、转写、网络名与账号名（见 support-bundle.md）。
