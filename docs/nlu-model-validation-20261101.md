### 下一步边界

当前 [负样本生成](<../tools/nlu-trainer/train.py#L148-L151>)使用单一长前缀 `取消这个请求，不要执行：…`，没有充分覆盖自然短否定、引用和假设表达；帮助正例也主要是 64 条窄模板。后续应补独立的真实口语与困难负例，并为规则和模型共用的执行入口补充请求性质、否定范围和歧义澄清约束，而不是只调置信度阈值。任务内容中的“不要”（如提醒我不要熬夜）和真正取消请求必须区分，不能简单按包含“不/不要”一律拒绝。这些仍是后续改进建议，本轮未实现或重新训练第二个修补模型。

## 模型效果口径

评测共 34 条手写样例：标准正例 6、未见口语表达 12、闲聊/否定/引用负例 12、歧义/需澄清例 4。样本规模小，不是统计代表性测试集。

- 原始标签正确：忽略阈值，top-1 类别等于人工预期。
- 正例可接受：类别正确且置信度至少 `0.75`。
- 负例不接受技能：`other` 或置信度低于阈值。**这里是模型决策指标，不代表生产已经正确处理 `other`。**
- 本地评测由下载的真实模型字节、配套 tokenizer、labels 经 CPU ONNX Runtime 执行；本地耗时不代表 NAS 耗时。

## 动态技能与调度架构边界

用户讨论的一次性/周期性任务、条件判断、步骤编排和受限脚本，应采用稳定的 Rust 能力 API + 配置驱动技能，而非每新增技能就硬编码、编译 Rust。**本轮没有实现调度 API 或 Python worker**；前述设计示意不能当作现有接口。当前已有动作只有受支持的 reply/end-session/MCP 等，新增帮助技能属于 reply。未来如实现脚本，应是受限 worker 调用白名单能力，不把文件上传变成服务器任意代码执行。
