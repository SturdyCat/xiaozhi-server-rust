## 模型效果口径

评测共 34 条手写样例：标准正例 6、未见口语表达 12、闲聊/否定/引用负例 12、歧义/需澄清例 4。样本规模小，不是统计代表性测试集。

- 原始标签正确：忽略阈值，top-1 类别等于人工预期。
- 正例可接受：类别正确且置信度至少 `0.75`。
- 负例不接受技能：`other` 或置信度低于阈值。**这里是模型决策指标，不代表生产已经正确处理 `other`。**
- 本地评测由下载的真实模型字节、配套 tokenizer、labels 经 CPU ONNX Runtime 执行；本地耗时不代表 NAS 耗时。
- NAS 直推走 `hello.test=true` 后的 `nlu_test`，绕过规则、启发式和 LLM；专门诊断期间使用阈值 `1.0` 避免在新生产会话接受候选，完成后恢复 `bert_enabled=false`、阈值 `0.75`。

| 模型 | 标准正例 top-1 | 标准正例可接受 | 泛化正例 top-1 | 泛化正例可接受 |
|---|---:|---:|---:|---:|
| 旧模型基线 | 6/6 | 0/6 | 4/12 | 0/12 |
| 第一轮构建（旧 live 快照） | 6/6 | 0/6 | 4/12 | 0/12 |

最终模型的 12 条负例与 4 条歧义例没有达到阈值的技能误接受，但低正例召回不能视为模型可用；其中歧义例 top-1 全部仍为具体技能，只是被低置信度阈值拦下。当前规则路径另有误命中，见后表。

4. 保持正常阈值，使用新候选测试端点跑独立正例、泛化表达、闲聊、否定、引用、歧义和旧技能回归；检查类别正确、正例阈值通过及负例误接受，不只看 raw top-1 或 eval loss。
5. 只有效果通过后才明确采用并保存启用；核对保存结果和生效档位，以新会话验证实际路由。提醒动作仍只回复，槽位与真实任务调度另行验收。

## 动态技能与调度架构边界

用户讨论的一次性/周期性任务、条件判断、步骤编排和受限脚本，应采用稳定的 Rust 能力 API + 配置驱动技能，而非每新增技能就硬编码、编译 Rust。**本轮没有实现调度 API 或 Python worker**；前述设计示意不能当作现有接口。当前已有动作只有受支持的 reply/end-session/MCP 等，新增帮助技能属于 reply。未来如实现脚本，应是受限 worker 调用白名单能力，不把文件上传变成服务器任意代码执行。
