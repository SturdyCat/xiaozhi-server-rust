# PRD：NLU iot 域语音控制 Tuya 设备（首期：智能插座开关）

- 项目：xiaozhi-server-rust（NLU iot 域落地）
- 编写：产品经理 许清楚
- 原始需求：「目前有智能插座，通过 nlu 打开/关闭指定名称的 tuya 设备」——把上一期预留的 NLU iot 域落地：语音「打开客厅插座 / 关闭客厅插座」控制局域网内已同步的 tuya 智能插座。

## 产品目标

用户对小智说「打开/关闭 + 设备名」，即可控制局域网内已同步的 tuya 智能插座，全程零云依赖（NLU 本地推理 + 本地 Tuya 控制链路）。三个正交目标：

1. **可用**：说出「打开<设备名>」「关闭<设备名>」即可成功开关插座，成功/失败均有自然语音反馈。
2. **鲁棒**：名称匹配失败、设备离线、DP 不支持等所有异常都以 speech 话术收尾，不中断会话。
3. **可运营**：技能在管理台 IoT 组可见可编辑，重训流程清晰（用户手动提交），为后续灯、窗帘等品类扩展留好架构口子。

## 用户故事

1. As a 终端用户, I want 说「打开客厅插座」就能让客厅插座通电 so that 免动手、免看手机。
2. As a 终端用户, I want 说「关闭<设备名>」立刻断电 so that 安全省心。
3. As a 终端用户, I want 设备名说错或模糊时收到「未找到/说得更具体些」的提示 so that 知道怎么修正，而不是系统沉默或崩溃。
4. As a 终端用户, I want 目标设备离线时被告知 so that 明白是设备问题而非我说错了。
5. As a 管理员, I want 在管理台技能列表 IoT 组看到 iot_device_on/off 两个技能并可编辑模板 so that 后续可自行调整说法。
6. As a 管理员, I want 新增 2 个训练标签后有明确的重训提示（旧模型不认识，需手动提交训练） so that 语音不生效时知道原因。

## 技术规范

- Language: 中文
- Programming Language: Rust（沿用现有服务端栈，架构师细化）
- Project Name: `nlu_iot_voice_control`

### Requirements Pool

**P0（Must have）**

| ID | 需求 | 说明 |
|----|------|------|
| P0-1 | 技能 `iot_device_on` | domain=iot，模板如「打开{device_name}」，action 静态写死 on，独立技能不共用开关值槽位 |
| P0-2 | 技能 `iot_device_off` | domain=iot，模板如「关闭{device_name}」，action 静态写死 off |
| P0-3 | 开放槽位 `device_name` | values 置空，与 task/delay 同模式 |
| P0-4 | NLU 种子训练数据 | 两技能的种子语料落库；**重训由用户在管理台手动提交**，本期只落代码与种子 |
| P0-5 | plan 能力 `tuya.control` | 能力白名单新增，args: name + action；执行链路参照 weather.forecast 先例：第一步产出 speech 字段，plan 第二步 replies.say {{steps.0.speech}} |
| P0-6 | 设备名称匹配 | 本地别名(alias)→云名称(name)，先精确后包含匹配 |
| P0-7 | 开关 DP 下发 | 调用 TuyaEngine.set_dp(device_id, dp, value)，开关型 bool DP（id=="1" 优先，识别策略由架构师细化） |
| P0-8 | speech 话术全集 | 成功确认；0 命中「未找到」；多命中歧义提示；设备离线（复用引擎三归类 offline/timeout/unsupported + 建议话术）；不支持开关 |
| P0-9 | 失败不崩会话 | 所有失败路径走 speech 话术，会话正常延续 |

**P1（Should have）**

| ID | 需求 | 说明 |
|----|------|------|
| P1-1 | 管理台 IoT 组占位口径核实 | IoT 组「规划中」占位文案与真实技能出现后的共存/消隐逻辑需核实，预计零改动但需确认文案调整 |
| P1-2 | docs/skill-catalog.md 更新 | 技能数 16→18，iot 域从占位改为正式域说明 |

**P2（Nice to have，不在本期）**

| ID | 需求 | 说明 |
|----|------|------|
| P2-1 | 更多品类 | 灯调光、窗帘等非开关型 DP |
| P2-2 | 别名语音引导 | 未命中时提示「你可以说：打开<别名>」 |

### UI Design Draft

无新 UI。管理台技能管理页（按域分组）自动落入新技能，仅在 IoT 组占位文案上可能有文案级调整（P1-1）。

### 铁律（架构师须遵守）

- `end_session` / `other` 为保留标签，不得占用或重定义。
- 技能动作中的工具名为静态字面量，不做动态拼接。
- 不改动已有 16 个技能名及标签，避免影响旧模型训练数据。
- 失败统一走 speech 话术，禁止抛错中断会话。

### Open Questions（待确认）

1. **成功话术口径**：确认语「已打开客厅插座」念用户说的别名，还是 tuya 云端名称？（建议：念匹配命中的本地别名，更贴近用户原话）
2. **包含匹配多命中混合状态**：精确/包含匹配命中多台设备且在线+离线混合时，是否优先在线设备，还是直接报歧义？（建议：歧义话术不自动选择，更安全）
3. **开关 DP 识别不到**：设备目录中无 bool 型开关 DP 时，话术归类为「不支持开关」还是「设备异常」？（建议归入 unsupported，复用现有建议话术）
4. **重训引导文案**：管理台是否需要为新增 iot 标签展示「需重新训练后生效」的提示？（建议 P1 顺带核实）

## 验收标准（摘要）

- 重训后说「打开/关闭 + 已同步设备名」能正确开关对应 tuya 插座，≤1 次澄清。
- 未找到/歧义/离线/不支持四类失败均有对应话术且会话不中断。
- 管理台技能列表 IoT 组展示两个新技能，已有 16 技能模板与标签零变更。
