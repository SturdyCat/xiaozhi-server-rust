# PRD：Tuya IoT 设备集成（局域网控制 + 管理台设备管理）

> **归档说明（归档波次：W15-2，旧端软下线）**：本文为 gearui-kit/echomuse/tuya 计划与验收/架构 原文，文中「Kuikly / GearUI / gearuiKit / client/shared / publishWeb / h5App/web / sharedCompose」等均为当时旧端口径，**保留史实、不作现行实现依据**。当前管理台为 `client/admin-web`（React + Vite + shadcn/ui + Tauri 2，生产静态目录 `client/admin-web/dist`）；见 [admin-web 指引](<../../client/admin-web/AGENTS.md>) 与 [W15 资产盘点归档](<./admin-web-migration/w15-legacy-assets-research.md>)。

## 1. 项目信息

- 项目名称：xiaozhi-server-rust / tuya-integration
- 技术底座：服务端 Rust + tokio + axum；管理台 Kuikly Compose + GearUI
- 核心依赖：`rustuya`（crates.io 0.3.0，Tuya LAN 协议 3.1–3.5 + device22，async/tokio）
- 明确不采用：TuyaOS/TuyaOpen C SDK（设备端固件 SDK，与"控制已有设备"错位）
- 原始需求：集成 tuyaos sdk，用以控制局域网的 tuya iot 设备，提供 UI 界面管理设备以及查看设备详细信息

## 2. 产品定义

### 产品目标

让管理员在小智管理台统一管理家庭局域网内的涂鸦 IoT 设备：涂鸦云仅用于配置凭证与周期/手动同步设备目录（local_key、名称、模型、在线状态），日常的设备发现、状态读取与控制全部走纯局域网（UDP 6666/6667/7000 发现 + TCP 6668 控制），零云依赖、低延迟、断云可用。

### 范围口径（本期 / 非本期）

- 本期：管理台 UI 设备管理（列表、控制、DP 详情）+ 局域网控制能力
- 非本期：语音控制（NLU iot 域技能，如"打开客厅灯"）——NLU 侧 domain 枚举已预留 iot 占位，本期不动 NLU
- 定位：tuya 设备是另一类受管设备，不接入语音会话链路；ESP 设备管理（现有 devices 导航）不受影响

### 用户故事

1. 作为管理员，我想在管理台配置涂鸦云开发者凭证（access_id/access_secret、区域），以便服务端能通过 OpenAPI 拉取我账号下的设备清单。
2. 作为管理员，我想一键（或定时）同步设备目录，把 local_key、设备名称、模型、在线状态落到本地库，以便局域网控制有据可依。
3. 作为管理员，我想在设备列表中看到所有涂鸦设备及实时在线状态，以便快速掌握家庭设备概况。
4. 作为管理员，我想对设备执行开关、布尔、数值类 DP 控制（如开关插座、调亮度），以便验证并使用局域网直控能力。
5. 作为管理员，我想查看单台设备的 DP 数据点详情（当前值、类型、可写性），以便排障和理解设备能力。
6. 作为管理员，当局域网直连失败（设备离线/协议不匹配）时，我希望得到明确的降级提示与建议动作，而不是无反馈的失败。
7. 作为管理员，我想手动触发一次同步并看到同步结果反馈，以便在新增/移除设备后立即更新目录。
8. （下期预告）作为家庭用户，我想通过语音"打开客厅灯"控制涂鸦设备——依赖 NLU iot 域技能，本期仅预留，不交付。

## 3. 技术规范

### Requirements Pool

**P0（Must have）**

| # | 需求 | 验收要点 |
|---|------|---------|
| P0-1 | 云凭证配置 | 管理台可录入 access_id/access_secret/区域，保存到服务端配置（走现有 SQLite 保存态快照 + revision 热生效机制）；凭证不可在 UI 明文回显 |
| P0-2 | 设备清单云同步 | 通过涂鸦云 OpenAPI 拉取设备清单（含 local_key、名称、模型、在线状态），落库；同步有记录（时间、结果、数量） |
| P0-3 | 局域网发现与控制 | 基于 rustuya 实现 UDP 发现 + TCP 6668 控制，支持开关/布尔/数值类 DP 下发与状态读取；服务重启后可重连 |
| P0-4 | 设备列表 UI | 管理台展示涂鸦设备列表：名称、模型、在线状态、同步时间；与现有 ESP 设备列表有明确区分 |
| P0-5 | 设备详情 UI（DP 实时状态） | 展示设备 DP 列表及当前值，控制操作有即时状态回显 |
| P0-6 | 控制失败降级提示 | 局域网直连失败时给出明确原因归类（离线/超时/协议不支持）与建议动作（重新同步/检查网络） |

**P1（Should have）**

| # | 需求 | 说明 |
|---|------|------|
| P1-1 | DP 语义化展示 | 按产品模型/标准指令集映射常见品类（插座/灯/窗帘），展示友好名称与控件形态（开关/滑条/百分比） |
| P1-2 | 在线状态心跳/轮询 | 周期性局域网心跳或状态轮询，维护设备在线状态缓存 |
| P1-3 | 手动同步按钮 | 列表页提供"立即同步"入口，带同步进度/结果反馈 |
| P1-4 | 设备重命名 | 本地展示名（local alias），不影响云端名称 |

**P2（Nice to have）**

| # | 需求 | 说明 |
|---|------|------|
| P2-1 | 分组/房间管理 | 按房间/分组组织设备，为下期语音控制（"客厅灯"）打基础 |
| P2-2 | 多区域凭证 | 支持配置多套区域凭证 |
| P2-3 | NLU iot 域技能接入预留 | 仅文档说明扩展点，不实现 |

### UI Design Draft（管理台）

- 入口：管理台新增涂鸦设备管理入口（放置位置待确认，见 Open Questions），遵循 AdminShell 导航与 GearUI 浅色主题规范
- 列表页：设备卡片/表格（名称、模型、在线状态点、同步时间），顶部为凭证状态条 + 同步按钮
- 详情页：设备基本信息区 + DP 实时状态区（按可写性区分"可控制/只读"），控制操作行内完成
- 铁律：.kt ≤600 行、只用 stateVar/stateListOf、GearUI 组件、禁止 observable/vfor/旧 DSL

### 边界与依赖

- rustuya 的协议细节（各版本协议握手、加密、device22 心跳）由架构师/实现阶段核实，PRD 不锁定 API 细节
- 涂鸦云 OpenAPI 仅用于目录同步；控制与状态读取不依赖云
- 不改动 workflow/gateway/NLU 现有链路

## 4. Open Questions（待确认）

1. 云同步周期：仅手动触发，还是支持定时自动同步（如每日一次）？
2. 凭证与 local_key 的安全存储：SQLite 明文是否可接受，还是必须提供加密存储选项？
3. 管理台入口：放在现有 devices 导航下做二级页，还是新增一级导航（涂鸦设备）？
4. 控制会话并发/超时口径：单设备同时只允许一个控制请求？控制超时阈值多少（建议 3–5s）？
5. 涂鸦云 OpenAPI 免费额度限制是否需要同步频率上限（如最小同步间隔）？
6. 局域网控制失败的降级是否需要尝试云端控制兜底，还是本期明确纯局域网、失败即提示？

## 5. 衡量标准（建议）

- 局域网控制指令端到端延迟 < 500ms（局域网内）
- 同步后设备清单准确率 100%（与涂鸦云账号一致）
- 控制失败时 100% 有明确降级提示，无静默失败
