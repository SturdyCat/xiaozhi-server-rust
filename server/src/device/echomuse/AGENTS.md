# EchoMuse 设备入口

继承[应用层指引](<../AGENTS.md>)。Echo Dot 2（emOS）经 EchoMuse 设备协议直连的**第二设备承载**，与 xiaozhi WS 共用同一条会话流水线；设计、协议映射表、蓝牙代理与不做范围见[根文档](<../../../../docs/echomuse.md>)，此处只列维护约束。

- 文件分工：[`frames.rs`](<frames.rs>) 是 `/em/data` 二进制帧的唯一编解码出口（帧型按方向分命名空间，不在此文件之外解析）；[`transport.rs`](<transport.rs>) 实现 `Transport`（只翻译原生 mono PCM：上行 mic 16kHz、下行 speaker 48kHz，均 40ms；上下行均不构造 Opus 编解码器）；[`routes.rs`](<routes.rs>) 是两条 WS 路由 + 只读状态查询 `GET /em/status`（关闭时也 200 + `enabled:false`，devices 取 hub key）+ control/data 两个 inbound 任务 + hub 认领（data 首帧是上游固件的 Text identify `{"type":"identify","device_id"}`，凭它精确认领；identify 后 data 面恒为二进制，再收 Text 忽略不断链）+ 唤醒/按键开轮 `start_turn`（顺序 **detect → mic_start → listen start**：detect 先投是 `[wakeup]` 唤醒问候语的触发点，问候关闭时仅多一行会话日志；`oww_wake`/`button` 的来源标签随 detect 的 `text` 透传会话层——`"本地唤醒词"`/`"action 键"`，`handle_control_text` 同步打 `触发来源` 日志，会话层日志据此区分唤醒与按键；sink 泛型只为测试可驱动）；[`registry.rs`](<registry.rs>) 把 register 的静态元数据（label/approved/版本/能力表/首末见时间）upsert 到数据目录 `echomuse_devices.json`（online 由 hub 实时合并不落盘）；[`admin.rs`](<admin.rs>) 是 `/api/echomuse/*` 管理面（经 `auth_ok` 鉴权，enabled=false 全 404；列表/详情/认领/下发 command/每设备 settings/删除登记记录（DELETE 与 POST .../delete 别名，清理 mock 设备用），command 在线 202 经 `PendingDevice.ctl_tx` 下发、离线 409，settings 白名单过滤后持久化到 registry 并在线即时推送/离线待接入推送；变更通知走管理台 WebSocket `GET /api/admin/ws`（见 `gateway/ws/admin_ws.rs`：hello 带当前设备面版本号、变化推 `echomuse_devices_changed`、ping/pong 应用层心跳），`/devices/wait` 长挂轮询端点已删除，设备面版本号仍在 mod.rs 的 watch 通道（hub 登记/移除与登记变更时自增，必须用 `send_modify` 锁内递增：无订阅者也更新且并发不丢递增；列表先读游标后取快照）；`json`/`gate` 与 BLE 管理面共用；API 细节见[根文档](<../../../../docs/echomuse.md>)管理面一节）；[`ble.rs`](<ble.rs>) 是蓝牙代理（`[echomuse].ble_proxy`）：`BleLink` 请求关联（`0x08` req/result）+ 广播/事件/槽位采集，GATT 请求构造纯函数与 `/api/echomuse/devices/{id}/ble/*` 端点（复用 admin 的 gate，`ble_proxy=false` 统一 404）；[`config.rs`](<config.rs>) 持 `[echomuse]` 配置段（`enabled`/`token`/`ble_proxy`/`plain_port`/连接欢迎语 `welcome`，`connect_welcome` 是会话启动欢迎语决策纯函数，回归在 [`config/tests.rs`](<config/tests.rs>)；欢迎语成品经预取/水库链路落盘 `hot-audio/`（裸 24k PCM 文件，见 `app::hot_audio`））；[`mod.rs`](<mod.rs>) 持 hub（条目**存活到会话结束**，data 认领取走 `data_rx`、data 任务退出经 `hub_restore_data` 归还——链路闪断重拨不必等下次 register，见 `hub_claim_data`/`hub_claim_only`/`hub_restore_data`/`hub_data`/`hub_ble`）、ack/config 文本（`config_baseline` 合并 ble 基线与每设备 settings，`wakeWordEnabled` 单独成条）与 mDNS 广播；[`listen.rs`](<listen.rs>) 把设备面路由**额外**监听到控制器专用端口（`[echomuse].plain_port`，默认 8767=官方明文 controller 端口，0=关闭；绑定失败回退主端口，mDNS 广播跟随实际监听端口；门控与 bind/serve/冲突回退回归在 [`listen_tests.rs`](<listen_tests.rs>)，不起 Engines）。
- 系统管理见 [`system.rs`](<system.rs>)/[`shell.rs`](<shell.rs>)：仅固定 info、日志源和严格 `confirm:true` 重启，无交互 shell/任意命令/OTA；管理面鉴权看 `server.expected_token`（空 = 局域网默认可管理；非空 = 必须 token，产品决策 2026-10）；设备侧看 `echomuse.token`（空 = 信任局域网设备，非空 = 设备必须带 X-Em-Token），已登记 approved + base_os=emos + authenticated 在线 control 才能请求，设备 `/shell/{device_id}` 还需 token + TCP peer IP + 当前 control channel + 未认领 pending 全匹配（不用 forwarded header）。一设备一操作，15s 总 deadline、64KiB 输出上限、随机 exit 哨兵跨帧聚合；EOF/超时/非0 exit/超限均失败，RAII 仅清自身槽，先 enqueue shell_close 再释槽。重启只确认后台 `kill -TERM 1` 已调度，202 `rebooted:false` 不是已重启证明。
- [`runtime.rs`](<runtime.rs>) 的状态仅属于当前 control（断线/重连清空）；随机 `session_id` 在列表/详情/runtime 同源投影，不落盘、不作鉴权，同一 hub 锁读取在线时长和身份，客户端凭它检测未观察到离线的快速重连。stats 只缓存有界已知标量，缺失为 null、不假填0；volume_set 仅 approved emOS + speaker 能力、整数0..127，下发202不乐观改volume_state。[`settings.rs`](<settings.rs>) 处理旧持久化 bool/number 兼容：owwOnDevice 线形为 off/shadow/on、wakeSoundLevel 为 quiet/medium/loud（旧数字无有效单位，恢复medium）、wakeMic 为0..6整数、阈值(0,1]；部分 settings 更新必须 merge 保留未提交键。旧 command/reboot 禁止，改走确认系统接口。
- bounded-turn 映射以当前代码为准（上游 858987c `device-controller-interface.md`）：[`turn.rs`](<turn.rs>) 维护当前 `LiveControl` 独占、data claim 捕获共享的 gate；唤醒/按键依次 `listen detect` → `mic_start{lock_mic:true}` → `listen start`。重复唤醒忽略；[`uplink.rs`](<uplink.rs>) 直接投带时长/字节预算与 data/capture epoch 的原生 PCM；`0x04` 投 epoch 化 `AudioBoundary(Speech)`，不为 VAD 补 Opus 帧；`0x05` 令该 capture 的已排队 PCM 失效并投 `NoSpeech`，两者立即重置 gate，重复/空闲哨兵幂等，不等 TTS EOS 才允许下一次唤醒。core 在 Speech flush+reset VAD 后识别、NoSpeech 丢弃+reset 且不识别；普通 ESP `listen stop` 语义不变。data 断线仅在 `hub_restore_data` 同会话探针通过后取消本轮，旧 control/data 不得按 device_id 操作新会话 gate。
- speaker EOS 必须解析真实 `ServerMessage::Tts{state:"stop"}.to_json()` 的 `type=tts,state=stop`，不能匹配伪造 `tts_stop` 或字符串子串；先补齐残 PCM `0x02` 再发一条 `0x03`，其他文本忽略。契约回归见 [`transport_tests.rs`](<transport_tests.rs>)；连续多轮/重复哨兵/尾帧/无语音回归见 [`turn_tests.rs`](<turn_tests.rs>)、[`uplink_tests.rs`](<uplink_tests.rs>)。默认 feature 的 Opus 编解码是编译桩，不能替代真实 sherpa/固件音频联调。
- 能力协商是兼容性契约：`ack.features` 只声明服务器支持的子集；`ble_connect`/`ble_adverts_data` 仅在配置开启且设备 register 声明 `ble_connect` 时条件追加（双向声明才启用，协议"未声明即降级"）；不声明的能力（`listen_session`/`audio_mix`）**不要**解析对应帧型，`0x06/0x08` 也只在 `ble_proxy` 开启时翻译。
- BLE 管理面由 [`ble_http.rs`](<ble_http.rs>) 与严格字段构造 [`ble_request.rs`](<ble_request.rs>) 承载（`ble.rs` 保持公开路由出口）。adverts/state/gatt 都要求双非空 token、管理鉴权、approved、ble_connect 和 authenticated 在线 control；GET 可带 query `session_id`，GATT body 可带 `session_id`，不匹配 409，成功顶层始终含 device_id/session_id。单台扫描/连接关闭不阻止读既有快照；GATT 必须有效 bleProxyEnabled/bleProxyConnections 都开启且 data 已认领。capture 一次 hub 锁抓 control/data/BleLink/session，发送同锁校验、等待变更时早退，RAII 仅清 captured Arc 内同 owner 请求，不能按 id 清新会话。35s deadline、16 pending、write 最多 512 decoded bytes、handle 1..65535、req 严格 u32；入站 GATT 64KiB、单事件/广播 4KiB、事件环100/快照50、广播表/单批次256。设备 ok:false 是 HTTP200 的有效失败，不能当动作成功；slots 按 t=slots 且无 ok；services 的 chars[].value_handle 才是读写地址，handle 是声明，props 为 bitmask，descs 可找 CCCD 0x2902 后普通 write 订阅，服务字段允许空/省略；不另造 subscribe 操作。实际 loopback HTTP、六操作、取消、deadline、重连与 owner 回归在 [`ble_http_tests.rs`](<ble_http_tests.rs>)，无真机命令。
- BLE 数据面收尾唯一出口是 `hub_restore_data`：持同一 hub 锁，按 hub→BLE 顺序 reset（推进 `data_epoch`、取消旧 pending）、按接收队列长度快照丢弃断线前已排队帧，再归还 data_rx；不在 data_loop 中先独立 reset，避免 reset/归还间接收新请求。GATT capture/check 校验 data_epoch，即使 control、mpsc channel、BleLink Arc 均未变化而立即重新认领，也必须拒绝旧 capture，不能让旧写入随重拨重放。`hub_data/hub_ble` 按ID助手仅保留 fixture，生产不可复用。对应回归见 BLE HTTP lifecycle 与 hub_tests。
- 会话无 xiaozhi hello：[typed media](<./media.rs>) 与 `session_params` 固定为 mono PCM S16LE / 40ms，**上行 mic 16kHz、下行 speaker 48kHz**（`AudioFormat::echo_mic`/`echo_speaker`，协议常量，不跟随 `[audio]` 的 ESP 24k/60ms）。48k 来自上游线缆契约（controller 用 ffmpeg 解到 48kHz mono 发 `0x02`，设备 DAC 48k 且不重采样）——按 16k 发会被当 48k 播成 3 倍速尖叫。ESP 保留 Opus 和 v1/v2/v3。Echo 无设备播放 ACK，不宣称已播放，也不套用未经证明的 ESP 固件队列容量，lead 固定为0。
- [media](<media.rs>) 用独立时长与字节额度限制输入/输出排队；NoSpeech/过载取消 capture，data/control 代际令旧 PCM/结束事件/PCM写回执/EOS失效。PCM与EOS都有同序 write ticket，旧回执清理只在原代际仍当前时取消，不得断开快速重拨的新 claim。BLE 的 hub→BLE 锁序、data_epoch 与归还前快照 drain 不变。
- [data writer](<data_writer.rs>) 在下行 socket 背压时继续处理入站 sentinel/EOF，并独立响应控制断线；只有 WebSocket send 成功才回复 socket-written，不把 mpsc 入队当作网络写入或设备播放。fake blocked-sink 回归在 [writer tests](<data_writer/tests.rs>)。
- `[echomuse]` 属 RestartOnly，已登记 `registry::APP_SECTION_HOT`（护栏测试会抓遗漏）；改动本段需重启。
- 系统管理外置测试为 [`shell_tests.rs`](<shell_tests.rs>)（slot owner/RAII、deadline、随机哨兵跨帧、输出限额；真实 loopback WS 鉴权、peer/pending、固定命令 Text 输入与混合 Binary/Text 输出、EOF 失败，绝不运行真机命令）与 [`system_tests.rs`](<system_tests.rs>)（闭合日志白名单、确认、音量范围、授权策略、runtime 缺失/边界、settings 迁移与 merge）。
- 测试外置在 [`tests.rs`](<tests.rs>)（帧编解码/协商形状/transport 翻译/`/em/status` 状态形状/registry 落盘往返；共享助手 `temp_registry`/`reg_load`/`insert_probe` 也在此）、[`admin_tests.rs`](<admin_tests.rs>)（管理面响应决策 + 设备面版本号语义）、[`hub_tests.rs`](<hub_tests.rs>)（hub 认领/归还语义）与 [`ble_tests.rs`](<ble_tests.rs>)（BLE 帧形状/BleLink 状态机/广播合并/GATT 请求构造）；hub 相关测试经 `HUB_LOCK` 串行；真机联调用 `tools/echomuse_mock_device.py`（语音回路；BLE 联调需另补 `0x06/0x08` 模拟）。
